# MAIN6/7 投放 PWM 测试

遥控器 **9 通道**随 `sh flight/1_sensors.sh` 启用：中位两路均 **900 μs 全闭合**，低位两路均 **1350 μs 全打开**，高位不发指令、不回位。启动后的首个有效档位执行一次，此后换挡才发送，同档不重复；两路合并为一条命令，其他执行器保持不变。配置在 `flight/flight.yaml` 的 `common.rc_payload`，接收值 ≤1300 为低位、≥1700 为高位，其间为中位。只读 MAVROS 的输出量程和反向参数，不写飞控参数，也不更改任务投放记录。

起飞后悬停、输入 `1/2/3/4` 手动投放，使用 `sh flight/hover_drop.sh --height 1.0`，详见[悬停手动投放](../../flight/HOVER_DROP.md)。

两台相同投放装置各装两个物品，正式任务沿用投放编号 1～4，按下表依次发送并保持；成功回执推进计数，中间不关闭复位：

| 投放编号 | 物理输出 | 机构位置 | PWM（μs） |
|---|---|---|---|
| 1 | MAIN6 | 释放第一个 | 1190 |
| 2 | MAIN7 | 释放第一个 | 1190 |
| 3 | MAIN6 | 释放第二个 | 1350 |
| 4 | MAIN7 | 释放第二个 | 1350 |

关闭区间为 800～980 μs，默认关闭和复位均取 **900 μs**，不再用 1500 μs 回中。当前飞控读回 MIN=900，因此默认配置量程是 900～2000；本次没有修改飞控 MIN、频率或急停。两级投放和 MAIN6/7 手动 PWM 都拒绝超过 **2000 μs** 的值，即便飞控 MAX 更大也不放行。

`sh tools/payload/servo.sh open 1` 到 `open 4` 分别执行表中四步；`close 1`/`close 3` 关闭 MAIN6，`close 2`/`close 4` 关闭 MAIN7。`sh tools/payload/servo_reset.sh` 给 MAIN6、MAIN7 各发一次 900 μs 关闭保持。均可加 `--dry-run` 离线预览。运行新任务只清空软件进度，不自动发送复位；装载前由操作者执行关闭。

兼容的 `flight/magnet.sh release 1`～`release 4` 使用同一四投配置，通过已有任务管理器发送；其文件名保留。正式任务按缓存中的飞控物理 MIN/MAX、反向位换算，参数不存在时沿用配置量程。

当前手动接线是 MAIN6 → 功能 301、MAIN7 → 功能 302。在机载电脑任意目录运行：

```sh
sh /home/drone24/aquacore-nanjing/tools/payload/main67_pwm.sh
```

进入后输入 `6 900` 关闭 MAIN6，输入 `7 900` 关闭 MAIN7；逐次输入 `6 1190`、`7 1190`、`6 1350`、`7 1350` 可按四投顺序手动测试。每行只控制指定一路。输入 `q` 退出，保持最后输出。启动和退出均不发送舵机命令。

```sh
# 固定 MAIN6，随后按需输入 900、1190、1350 等 PWM 数值
sh tools/payload/main67_pwm.sh --port 6

# MAIN7 只发一次 1190 μs，释放第一个
sh tools/payload/main67_pwm.sh --port 7 1190

# 完全离线预览，可在没有 ROS 的电脑运行
sh tools/payload/main67_pwm.sh --port 6 1190 --dry-run
```

同样支持 `--fcu-url`。MAIN6/7 的离线默认范围是 900～2000 μs，来自 2026-10-25 参数快照；在线按各路飞控 MIN/MAX 和反向位换算。MAIN6 使用命令 187 的 param1、MAIN7 使用 param2，其余通道为 NaN，不按物理端口号直接填命令参数。

每次只校验所选端口及其功能是否被其他 MAIN/AUX 输出复用。双路菜单会显示两路映射问题，其中一路配置错误不阻止测试另一路。沿用已连接、未解锁、范围和重复映射检查，不修改飞控参数或自动投放配置。实际位置仍需观察确认。日志位于 `data/main67_pwm/<时间>/`。

## 原 MAIN1 入口

MAIN1 入口仍保留，默认控制 MAIN1；现在接到 MAIN6/7 时请使用上面的新入口。

在机载电脑的项目根目录运行（需要现有 ROS Noetic/MAVROS 环境）：

```sh
# 交互输入：每次输入一个 PWM 微秒值并回车；q 退出
sh tools/payload/main1_pwm.sh

# 只发送一次 1500 μs，然后退出
sh tools/payload/main1_pwm.sh 1500

# 离线预览：不启动 ROS、不连接飞控、不发送命令
sh tools/payload/main1_pwm.sh 1500 --dry-run

# 显式指定飞控连接；未指定时沿用现有 PX4 USB 自动发现
sh tools/payload/main1_pwm.sh --fcu-url 'serial:///dev/ttyACM0:921600'
```

不带数值的 `--dry-run` 只显示配置范围和 MAIN1 功能映射，不进入交互菜单。
支持 `--config` 和 `--flight-config` 读取指定配置；默认仍按机器配置与 `delivery-route` 配置合并。

每次有效输入只请求一次持久 PWM 输出（命令 187）。启动不发送初始值，退出、Ctrl+C、EOF 均不追加回位指令；没有 2 秒恢复或 3 秒时长上限。飞控接受后保持至下一次舵机指令，飞控重启后需要重新发送。示例中的 1500 μs 只是测试值，不代表机构的闭合或投放位置。

脚本固定控制物理 MAIN1，按 `payload.actuator_indices['1']` 指定的执行器通道寻址，默认期望 `PWM_MAIN_FUNC1=301`。沿用已有的连接、未解锁、PWM 范围与映射检查；MAIN2～4 的无关配置不阻止测试，但 MAIN1 的功能被其他 MAIN/AUX 输出复用时仍拒绝发送，以免同时驱动其他输出。

实测按飞控 MAIN1 当前 MIN/MAX 和反向参数换算，允许测试实际量程内且不超过配置命令上限的值。飞控未提供的 MIN/MAX 沿用配置值并提示。离线预览使用当前配置范围 900～2000 μs，且按未反向计算。脚本不修改飞控参数、正式投放配置或任务状态。

连接流程复用现有地面测试工具：使用 `127.0.0.1:11341` 上的 MAVROS，或自行启动仅用于测试的 MAVROS；退出时只关闭自身启动的进程。传输异常不会自动重发，交互模式可继续手动输入。终端显示飞控接受/拒绝回执；机构是否实际到位或投放需观察确认。

每次实际运行的参数快照与请求、回执、错误保存在 `data/main1_pwm/<时间>/`。未连接的预览不会创建测试日志。

`servo.sh`、`servo_reset.sh` 读取当前双舵机四投配置，分别提供预设开合和关闭复位操作。
