# 南京版架构与状态机

定位链：MID360 → FAST-LIO → 按当前安装外参转为机体原点 → 固定局部 ENU → MAVROS 外部定位 → PX4。

飞行链：普通／九步录点文件 → 南京任务引擎 → EGO 航点与原生升降参考 → NativeRuntime → 既有 px4ctrl 原生接口 → MAVROS → PX4。底层规划、轨迹发送和飞控参数保持现状。

`FlightCore` 只负责起飞、导航到点、保持、投放回执和坐标降落生命周期。`NativeSegmentMixin` 提供原生坐标移动，`NativeFlightMixin` 提供起飞参考、保持及实际落地确认。普通航点和两圈航线分别由 `WaypointRouteEngine`、`DeliveryRouteEngine` 组织，不继承旧搜索或视觉引擎。

普通任务：TAKEOFF → APPROACH（逐点）→ COMPLETE（末点参考持续发送）。比赛任务：TAKEOFF → 第一圈逐点 → 第二圈逐点／DROP（下降至识别高度、红点取图、固定目标移动、下降、ACK、原有动作等待、回升）→ HOME → LAND → 实际落地上锁后 COMPLETE。

单点测试 `drop_test` 使用 `SingleDropEngine`：TAKEOFF → 指定 XY → 共用 DROP 流程（仅所选投放口）→ 实际起飞 XY → LAND → 实际落地上锁后 COMPLETE。它复用比赛参数和红点工作进程，不构造虚拟四点航线；原生初始化确定本次起飞基准后，再确定返航 XY。

保持、独立降落和人工接管会使后续任务停止推进，旧 EGO 会话和目标不能恢复输出。原控制接口、RPC start/status/events/hold/payload/manual_height/shutdown、录点格式和轨迹日志路径继续兼容保留功能。

红点公共计算链：DF200 → 共心靶标确认与红色质心 → 图像时间定位插值 → 近水平投影。独立预览只输出观察结果；比赛任务启动独立无窗口视觉进程，把带会话和图像序号的结果交给航线引擎。EGO 生命周期与视觉进程分开，视觉退出不会调用 EGO 的错误暂停流程。管理器只转发结果，图像计算不占用控制线程。

每次取图 15 秒；运动参考结束后宽限 15 秒。每点一次重拍，重拍后 XY 各放宽 8 cm、Z 不变；识别失败下降兜底，下降超时按实际高度释放。零偏移无附加动作。成功回执按航点记录，四个红点不按类别互相排除。除此之外不新增准入、停稳或消息限龄条件，保留原有实际控制权、回执及降落确认行为。完整规则见 [投放航线说明](../flight/DELIVERY_ROUTE.md)。
