## 已部署的修改

1. **统一数据文件。** `record_points.sh`、`record_drop_points.sh`、`fly_points.sh`、`drop_points.sh` 默认共用 `data/routes/waypoints.yaml`，写入统一 XY 格式。旧投放格式仍可通过显式 `--route` 读取，不按文件修改时间猜测、不自动退回旧文件。普通录点超过四点时，投放入口可先用现有 `--count 1..4` 选点。
2. **显示并记录实际来源。** 文件路径、SHA256、原始点数随本次任务配置保存，预览显示实际 XY；摘要对应一次读取的原始字节。机上预览已确认读取今天保存的 `(+1.798536,+1.314422)`，不再默认读取旧的 `(-2.304086,+0.554427)`。巡航仍为 `1.4 m`，投放仍为机上原有 `0.25 m`。
3. **用正在保持的参考衔接 EGO。** 目标与起点位置、速度、加速度绑定在同一条 `EgoGoalCommand` 消息中，通过每次 EGO 会话的 `goal_with_start` 发送。全局路径和首次局部规划都使用这个起点。起飞参考结束时，它是巡航高度及零速度/加速度；定位实测量仍用于地图与控制反馈。没有伪造或改写里程计，也没有新增到高、停稳等待或限高。
4. **处理首次连接回调竞态。** 实际启动入口中，ROS 可能先登记 TCP 订阅者并发送轨迹，再执行连接回调。现在保留交接参考直到首次连接回调被处理，防止紧接着又用实测 `+0.407 m/s` 重规划。重复目标不重新注入起点；执行器后续重连保留原有从当前实测状态重建的处理。
5. **定位诊断。** 保留原预测器缺口处理、时间限制及定位来源；增加 IMU/LiDAR 源时间间隔、回调到达间隔、ROS 序号缺口、接收时刻与源时间差、准确的预测缺口两端和当前恢复状态。缺口区间计数与 withheld 回调次数分开。诊断进入原有 `alignment_control.jsonl`，不作为新准入条件。IMU ROS 订阅启用 TCP_NODELAY，减少小消息合并等待，但不据此声称已经消除底层丢包。

机载管理器保留该机已有的“红点进程仅在取图窗口运行”版本。它与本地副本不同，部署时以机载备份为基准只合并交接改动。四投回执、两阶段对准、15 秒兜底、重拍、hold 和降落规则均未改动。
