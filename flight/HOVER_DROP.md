# 起飞悬停后手动投放

保持 `1_sensors.sh`、`2_localization.sh`、`3_controller.sh` 三个终端运行，再开一个终端：

```sh
cd /home/drone24/aquacore-nanjing
# 预览，不连接 ROS 或执行动作
sh flight/hover_drop.sh --height 1.0 --dry-run

# 原地起飞到设定高度，随后进入投放菜单
sh flight/hover_drop.sh --height 1.0
```

起飞沿用现有原生起飞流程，完成后后台持续悬停，终端接受每行一个编号。输入 `1` 后回车，再按需输入 `2`、`3`、`4`：

| 输入 | 动作 |
|---|---|
| `1` | MAIN6，1190 μs，第一档 |
| `2` | MAIN7，1190 μs，第一档 |
| `3` | MAIN6，1350 μs，第二档 |
| `4` | MAIN7，1350 μs，第二档 |
| `h 0.7` | 调整到本次起飞基准上方 0.7 m，完成后返回菜单 |
| `q` | 在当前位置降落，观察实际落地与停桨，结束菜单 |

每次输入只发送对应指令一次。可以指定任一编号；重复输入同一编号也会再次发送，不自动补发、不自动复位，也不自动执行其他编号。终端显示 MAIN 输出、PWM 和现有飞控回执。此次是悬停手动机构测试，不取图对准或自动下降投放。

默认读取 `flight.yaml` 的 `delivery-route` 配置，与比赛使用相同投放映射；不写 `--height` 时起飞高度为 1.4 m。支持现有 `--takeoff-speed`、`--takeoff-acceleration`、`--flight-config` 和 `--set` 参数。起飞及调高的完成判断、飞控控制权和手动投放回执处理均沿用已有实现，没有增加到高、停稳、重试或超时条件。

菜单等待输入时，Ctrl-C 或 EOF 退出菜单，后台继续悬停；需要降落可运行 `sh flight/safe_land.sh`。起飞或调高观察期间 Ctrl-C 沿用原任务的停止并保持行为，随后结束菜单。降落观察中退出不会撤销已提交的降落，也不会重新打开投放菜单。

需要飞向指定 XY、红点对准后自动投放并返航降落时，使用[单点投放测试](DROP_TEST.md)。
