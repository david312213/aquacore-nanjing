# 南京比赛录点与多圈航线

录点只订阅 `/airseafly/native/planning_odometry`，只记 XY。与飞行使用同次定位，不重置坐标。

只测试一个靶标和指定投放口时，使用 [单点投放测试](DROP_TEST.md)，无需录制比赛航线。

## 分段航线录点（默认，2026-11-19）

`sh flight/record_route.sh` 默认按四段录点，保存为 `version: 4 / mode: loops`：

| 段 | 内容 | 结束方式 |
|---|---|---|
| ① 进场点 | 起飞点进入巡航闭环途经的点，只飞一次 | 引导录 3 个，录满自动进入下一段；Enter 提前结束；不强制个数 |
| ② 巡航闭环 | 绕圈航点，首点不重复录；前 N-1 圈自动回到巡航首点闭环，**最后一圈从巡航最后一点直接飞到投放环第一点** | Enter |
| ③ 投放环 | 单独录的一套点，投放点按记录顺序编号 1～4 | Enter |
| ④ 返航点 | 投放环之后回 HOME 途经的点 | Enter，全部录完 |

按键：`h` 任何时候记录/覆盖 HOME；`1` 普通 / `2` 圆环 / `3` 投放（只能在投放环）只切换类型；空格把最新 X/Y 记到当前段；`x` 撤销最后一点并回到它所属的段；`q` 保存，`--resume` 继续。

飞行顺序：起飞 → 进场点 → 巡航闭环 `delivery_route_options.laps` 圈 → 投放环（投放点停下投放）→ 返航点 → HOME 降落。**`laps` 现在是巡航闭环圈数**，投放另飞一遍投放环；`laps: 0` 跳过巡航。可飞条件不变：有 HOME、有 1～4 个投放点；空的段直接跳过。固定轨迹下，进场、全部巡航圈和投放环中第一个投放点之前的点是一条连续航段（含局部配时），之后每个投放点、返航点到 HOME 各一段。各段之间的直线航段中间不能另加点，起飞前用 `--dry-run` 和轨迹预览检查。

旧的共用一套点录法用 `sh flight/record_route.sh --shared`，九步向导用 `--wizard`；旧文件照旧可飞，按原飞法，只是 `laps` 统一按巡航圈数解释：旧 `laps: N` 的飞法现在写 `N-1`。

## 共用航线录点（旧，2026-11-17）

绕圈和投放只录一套点，保存为 `version: 2 / mode: free`；`route` 同时用于满载绕圈和最后一圈投放。`b` / `d` 分路线切换已删除，HOME 单独记录一次。

读取旧 `version: 3 / mode: split` 文件时，使用包含投放编号的 `route` 作为共用航点，保留这些点的顺序、XY、类型和投放编号；原来的独立 `loaded_route` 不参与飞行，不再要求补录绕圈路线。续录保存为单路线格式。此次机载默认文件转换前的完整备份在 `data/deployments/20261117-single-route/before.tgz`，未填写的 HOME 仍保留为空，不推测坐标。旧 v1 九步向导保持可读和续录。

```sh
sh flight/record_route.sh
sh flight/record_route.sh --resume
sh flight/4_delivery_route.sh --dry-run
```

按希望飞行的顺序边走边记，点数自己定，每个点自己选类型：

```sh
sh flight/record_route.sh --resume data/routes/delivery_route.yaml
```

| 按键 | 作用 |
|---|---|
| `h` | 站在起降点记录 HOME；再按一次覆盖 |
| `1` | 切换为普通点（巡航高度），不记点 |
| `2` | 切换为圆环点（圆环高度、圆环速度），不记点 |
| `3` | 切换为投放点，不记点 |
| 空格 | 按当前类型记录最新 X/Y；之后打印已记点数和 HOME、每个点的坐标 |
| `x` | 删除最后一个航点；HOME 只能用 `h` 重新记录 |
| `q` | 保存退出，未录完也可以保存，`--resume` 继续 |

投放点按记录顺序编号 1～4：MAIN6 一档、MAIN7 一档、MAIN6 二档、MAIN7 二档。总圈数由 `flight.yaml` 的 `delivery_route_options.laps` 设置（默认 2，任意正整数）。前 N-1 圈满载按录制顺序走完、每圈回到第一个点；最后一圈同样顺序，到投放点停下投放，**投放圈也走完全部航点回到第一个点，再从第一个点回 HOME 降落**（2026-11-18 起）。第一个点到 HOME 是一段直线航段，中间不能录点，起飞前确认这条线上没有障碍。第一个点是投放点时，闭环回到该点不会重复投放。

录点保存且航线完整时，终端打印各圈的飞行顺序（按 `flight.yaml` 的 `laps`），`laps: 2` 时例如：

```text
第1圈：1.投放1 → 2.普通 → … → 17.投放4 → 18.普通 → 19.普通 → 1.投放1（闭环）
第2圈：1.投放1[投] → 2.普通 → … → 17.投放4[投] → 18.普通 → 19.普通 → 1.投放1（闭环）
返航：1.投放1 → HOME 降落
```

`--dry-run` 也打印同样的飞行顺序。

### 轨迹预览 HTML（2026-11-18）

录点保存且航线完整时，自动按 `flight.yaml` 的 delivery-route 参数生成固定轨迹预览，保存在航线文件旁边：默认 `data/routes/delivery_route_preview.html`，终端打印路径，用浏览器打开。图中有俯视 XY（按满载绕圈、投放圈、返 HOME 分色，▼ 为投放点，H 为 HOME，叠加记录边界）、高度和速度曲线、可拖动的时间轴、每段时长和飞行顺序。按 HOME 地面 Z=0 估算，投放下降、对准、降落不在图中；实飞每段从投放回升点重新生成。`sh flight/4_delivery_route.sh --dry-run` 也会重新生成，`--preview-html 路径` 可另存。生成失败只打印提示，不影响录点保存和飞行。

改圈数：`delivery_route_options.laps: N`（默认 2）。`laps: 1` 只飞一圈、边飞边投：按录制顺序飞，到投放点就停下投放，走完全部航点回到第一个点再回 HOME 降落；`laps: 3` 起为多绕满载圈。投放规则、到点判据和航段都不变。临时试一次可用 `--set delivery_route_options.laps=1`。旧名 `drop_lap` 已改为 `laps`，不再读取。

起飞前检查（已与用户确认）：没有 HOME、没有投放点，或投放点超过 4 个的航线不能起飞，`--dry-run` 直接报错；录点时记第 5 个投放点被拒绝。这些只在起飞前检查，飞行中不增加等待或限制。

绕障碍时在进弯、弯中、出弯都打点，离障碍近处每 0.5～1 m 一个；点之间是平滑曲线，不会照着你中间怎么走。圆环前约 1 m、环中心、环后各打一个圆环点，尽量共线。

## 九步向导（旧）

`sh flight/record_route.sh --wizard` 保留原来的固定九步顺序；以前录的航线照常飞，`--resume` 按文件自动选择模式。

| 步骤 | 内容 |
|---|---|
| 1 | 中央起降点 HOME，空格录一个点 |
| 2 | 投放点 1／绕圈起点，空格录一个点 |
| 3 | 绕障碍物 2 并前往投放点 2，空格连续录，回车结束 |
| 4 | 投放点 2，空格录一个点 |
| 5 | 从障碍物 3 与下边界、右边界之间绕行，空格连续录，回车结束 |
| 6 | 投放点 3，空格录一个点 |
| 7 | 圆环段至投放点 4，空格连续录，回车结束 |
| 8 | 投放点 4，空格录一个点 |
| 9 | 从障碍物 1 与上边界、左边界之间绕行返回投放点 1，空格连续录，回车结束 |

x 删除最后一点并退回所属步骤，不改变投放编号；q 保存退出，未完成的向导可以保存，使用 `--resume data/routes/delivery_route.yaml` 继续。绕行段数量不限。闭环复用投放点 1，最终降落复用 HOME，不重复录坐标。

```sh
sh flight/4_delivery_route.sh --dry-run
```

预览使用 [flight.yaml](flight.yaml) 的 `mission_profiles.delivery-route`，自动选择比赛参数。前 N-1 圈满载经过全部航点；最后一圈沿相同顺序，在投放点 1～4 直接下降至定位 Z=0.5 米、红点对准一次、到配置投放高度、单路释放并等待回执、原有 1 秒动作等待、回升。两只舵机各投两次，依次为 MAIN6 1190 μs、MAIN7 1190 μs、MAIN6 1350 μs、MAIN7 1350 μs；每次只改变目标舵机，保持输出且中途不回位。最后一圈投完后继续走完剩余航点、闭环回到第一个点，再返回 HOME 坐标并降落。

航点之间默认用固定轨迹航段（`navigation.backend: fixed_min_snap`）：每段到投放点或 HOME 停下，中间点连续通过；参考到投放点后按 `flight.arrival_radius_m` / `arrival_dwell_s`（XYZ 0.2 m / 0.5 s）判断到点才开始投放，到不了就原地悬停等待。回到 HOME（降落点）改按 `flight.home_arrival_xy_m`：只看水平距离，5 cm 内持续 0.5 s 才开始降落，高度不计；参考结束后超过投放的运动宽限（`visual_alignment.motion_timeout_margin_s`，两者共用）仍未进入，就在当时位置开始降落，不会卡住。投放后的下一段从回升终点出发。不运行 EGO、不实时绕障；`--dry-run` 列出每段时长和速度。圆环速度为 `planning.gate_velocity_mps`，每圈都生效。设 `backend: ego` 恢复原 EGO 逐点导航。

任务分为两个阶段：**满载绕圈 N-1 圈 → 投放阶段**。最后一圈满载圈闭环后立即进入第一个投放点的原生投放流程，没有新增阶段等待；`laps: 1` 没有满载阶段。终端航点状态区分“满载绕圈”和“投放阶段”。

从起飞后的首个航点开始，到最后一圈结束并返回 HOME，保持同一个 EGO 工作进程和地图更新。普通航点、闭环、两个阶段之间不重启 EGO；取图、对准、下降、释放回执、释放后动作完成及回升期间也保持地图运行，飞行参考由原生投放流程生成，不采用上一航点的 EGO 命令。每个新目标沿用已有目标标识隔离旧回执与轨迹。进入降落、人工保持或任务结束时仍按原流程退出 EGO。

### 一次红点开环对准

比赛任务从任务开始提前启动独立无窗口红点观察进程与相机（2026-11-15 起），相机在起飞、航点飞行和投放点之间保持运行；目标识别只在原有取图阶段运行。每次取图只使用该窗口新采集的图像，预热缓存和上一点的结果不参与对准。取图等待仍使用现场配置，不等待相机就绪，不另加等待。同一取图阶段内进程失败不自动重启，按原有超时兜底；后续新窗口保留启动机会。不需要另开红点预览。识别及投影参数共用 [red_point.yaml](red_point.yaml)，任务开始时冻结副本，各点不热更新。相机异常不停止导航。下文列出的 15 秒是流程确认时的值，运行时以该任务的 effective_config.yaml 为准，本次没有修改现场超时参数。

到投放点后不在高处取图，直接在录制航点 XY 上方以投放下降速度降至定位 Z=0.5 米，再取图；从原有绿环、白圆、红点共心确认的候选中，选离录制航点最近者，以真实红点质心执行一次固定目标移动，然后到配置投放高度。重拍时选离上次锁定目标最近者。移动期间图像不会更新目标。对准移动及两段高度运动使用 XYZ 各 5 cm，不额外等待停稳。

中间高度是定位 Z 的绝对值，不是相对本次起飞位置的高度或镜头离靶面距离；最终投放高度仍使用原有起飞基准配置，二者互不覆盖。中间下降轨迹结束后再过 15 秒仍未到位时，保持实测 XYZ 开始取图，横向对准保留该实际 Z。此分支不消耗重拍机会、不提前投放；取红点图仍最多等待 15 秒。中间下降超时单独记录，红点识别失败才进入原有下降兜底。

### 已确认的兜底

参数位于 `mission_profiles.delivery-route.delivery_route_options.visual_alignment`：

| 参数 | 默认 | 行为 |
|---|---:|---|
| `intermediate_height_m` | 0.5 m | 到投放点后直接下降至定位 Z=0.5 米识别红点 |
| `frame_timeout_s` | 15 s | 每次取图单独计时，空结果不重置计时；超时下降投放 |
| `motion_timeout_margin_s` | 15 s | 从参考轨迹结束算起，实际仍不到位时触发重拍或兜底 |
| `retake_limit` | 1 | 每个投放点一次额外重拍 |
| `retry_xy_relax_m` | 0.08 m | 重拍后 XY 各放宽一次，Z 不变；下一点恢复 |

识别超时后，有视觉修正就使用最后一次固定目标 XY，没有视觉修正就使用录制航点 XY，下降到配置投放高度。进入兜底后不再因迟到图像回到对准流程。

修正运动超时且尚未重拍时，保持当前 XY、保留原目标 Z，重新取当前阶段的一帧；第一阶段重拍成功后仍需中间下降和第二阶段；第二阶段重拍不重复中间下降。重拍后第一阶段按 XYZ 各 `[0.18, 0.18, 0.10]` m 判断，后续按 `[0.13, 0.13, 0.05]` m 判断，不累计。重拍仍失败就进入下降兜底。正常与兜底下降都判断 XYZ 到位；下降参考结束后再过 15 秒仍不到位，就保持实测 XYZ、按实际高度释放。

偏移继续使用 `delivery_route_options.mount_offsets_body_m`，按投放编号 1～4 填 `[前, 左]` 米，当前全零，零偏移没有附加动作。以后非零时，在下降后将安装偏移的负值按航向转换到世界 XY，只补偿一次；补偿超时也保持实测位置释放，不重复叠加。

原有飞控控制权、定位与舵机真实回执处理保持现状；没有新增其他准入、停稳或图像限龄条件。释放只发一次，一直等真实回执，不因等待过久重发。成功回执按当前航点记录，四个同为 `red_point` 的靶标均可投放；旧回执和重复回执不推进编号。`hold` 停止本任务并保留记录供查看，新任务清空，不新增继续任务命令。

地图持续运行指保持进程和正常局部点云更新；并未新增整圈历史点云永久保存功能。

### 最终 H 标对准降落

回到 HOME 巡航高度后，不再直接请求降落，而是按两次开环对准降落：高处识别 H 标 → 飞向固定 H 中心 → 下降至定位 Z=`intermediate_height_m` → 再识别 H 标 → 飞向固定 H 中心 → 以 0.30 m/s 下降至起飞基准上方 0.15 m → 请求原有 AUTO.LAND，由 PX4 触地判断并上锁。每次取图最多等 5 秒，超时不重拍，在当前保持的 XY 直接下降：第一次超时在 HOME 到达位置，第二次超时在第一次修正后的位置。修正移动与中间下降沿用 15 秒到位宽限和 XYZ 容差；末段下降参考结束即交 AUTO.LAND，不在近地等待到位。选靶规则同投放：第一次选离 HOME 最近者，第二次选离第一次目标最近者。

识别使用下视 YOLO11n 1016 版（`models/yolo11n_20261016/down/`）的第 6 类 `landing_pad`，参数在 [red_point.yaml](red_point.yaml) 的 `landing_pad`。每次等待 H 时，按取图窗口启动识别进程，带 `--target landing_pad`：只跑 H 识别、不跑红点；投放取图和其余阶段不加载 YOLO。机载系统 OpenCV 4.2 不能加载 YOLO11，识别进程另起 `runtime/yolo_fast/bin/python`（OpenCV 4.13）子进程推理；`runtime/yolo_fast` 链接到 `~/uav-aquacore/runtime/yolo_fast`，删除或改名 `~/uav-aquacore` 会使 H 识别失效。相机与模型启动时间计入 5 秒等待（相机冷启动约 2.3 s，模型约 0.7 s，二者并行），单帧推理约 225 ms。解释器或模型缺失、子进程 2 秒无回复，都按无识别处理，5 秒后直接下降，不停止任务。

离线用 2026-10-27 DF200 录像 453 帧验证：模型会把投放靶的绿环误判为 H（置信度 0.45～0.76），HOME 附近若有绿环靶需注意；该录像无真实 H 标，H 召回尚未用实拍验证。

参数位于 `delivery_route_options.landing_alignment`：`enabled`（默认 true；false 恢复原坐标降落）、`frame_timeout_s` 5 s、`final_height_m` 0.15 m、`final_speed_mps` 0.30 m/s。`drop_test.sh`、`drop_points.sh` 返回实际起飞 XY，不一定有 H 标，仍按原坐标降落。

比赛巡航 1.4 m、门段 1.6 m，2026-10-26 已确认地图上限改为 2.4 m。仓库投放默认 0.7 m，机载现场设置为 0.25 m，以对应机器的 `--dry-run` 为准。不把预览或模拟通过视为符合实际路线、投放高度或 5 分钟时限。

前三终端仍使用短命令；比赛任务启动时自动把比赛的 EGO 参数传给规划器。投放编号 1/3 映射物理 MAIN6（功能 301），编号 2/4 映射 MAIN7（功能 302）。关闭范围为 800～980 μs，当前关闭／手动复位值为 900 μs；程序禁止超过 2000 μs，启动任务不自动发送关闭指令。飞控频率、急停及输出参数不由任务脚本修改。本次逻辑已同步机载并完成编译，采用离线回放验证，尚未执行实机投放。部署备份与日志位于 `data/deployments/20261025-215126-delivery-single-test/`；机载保留现场定位预测、协方差模式和雷达盲区参数。

## 绕圈局部时间分配（2026-11-15）

`delivery_route` 的固定轨迹中，含绕圈闭环的首个航段启用局部平滑配时。该航段包含入场、前 N−1 圈，以及接入第一个投放点的导航。MINCO 空间曲线和全部航点保持不变，只优化沿曲线的行进速率；速度、加速度和圆环限速仍读取现场现有值，包含连续圆环段和单个圆环点。位置、速度、加速度和 jerk 连续，投放航段末端仍是原坐标、零速度、零加速度。

单圈投放、投放之间与 HOME 返航航段、`drop_test`、`drop_points` 和普通录点飞行保持原配时。原有到点判定、下降、红点对准、舵机成功回执、同点去重、hold 与降落流程不变。没有新增准入、等待、限龄、停稳或重试限制。

局部配时在任务原有的轨迹准备阶段求解，使用现有 SciPy；首个航段起点一致时直接复用起飞前准备的结果。50 Hz 运行时不调用优化器，使用序列化的平滑时间映射采样。无法求得更快参考或优化依赖不可用时，自动沿用原参考，并在预览和日志中说明，不因此拒绝任务。

`--dry-run` 显示局部配时采用情况、原/新参考耗时和逐圈拆分。航迹 JSON 保存时间映射，支持离线重放。更短的参考时间不等于实际任务耗时：加快后实机跟踪误差和滞后可能增大，也可能增加投放前原有到位等待。到点容差没有放宽，视觉流程不变，但不能由离线计算保证实际投放精度不变。该功能部署时未启动实机飞行。

## 投放相机预热（2026-11-15）

任务开始后提前启动相机和红点观察进程，起飞、绕圈、下降及投放点之间保持相机运行；这些阶段只接收图像，不运行目标识别。仍按原有下降流程进入红点取图阶段后，才识别该阶段新采集的图像，沿用图像时刻的位姿投影和一次红点开环修正。预热缓存、上一点和重拍前的结果不会用于新窗口。

不等待相机就绪，不改变现场取图/运动超时、到位容差、投放高度、偏移或释放规则。相机异常仍按现有取图超时兜底；同一取图窗口不循环重启，后续新窗口保留原有启动机会。返 HOME、hold 和任务结束会清理相机；H 标降落的两次对准及按窗口启停方式不变。

## 绕圈配时版本选择（2026-11-18）

`flight/flight.yaml` 的 `mission_profiles.delivery-route.navigation.timing` 决定满载绕圈段的配时：

| 值 | 含义 |
|---|---|
| `original` | 原配时 |
| `optimized` | 局部配时，只限速度/加速度（2026-11-15 版，比赛现用） |
| `thrust` | 局部配时，推力方向约束（2026-11-18 版，参数在同一 profile 的 `planning.retiming`） |

- 投放之间、回 HOME 的航段，以及 `drop_test.sh`、`drop_points.sh` 都不做局部配时。
- `--no-loop-retiming` 仍然临时改为原配时。
- 不写 `timing` 时与旧版相同：开启局部配时，即 `optimized`。
- `--dry-run` 会显示“绕圈配时版本”。
- `record_route.sh` 录点不受此项影响。

### `thrust` 求解失败时自动重解（2026-11-19）

`thrust` 用 SLSQP 求解。2026-11-19 两条现场航线上，它经常在起始点就停住（`Positive directional derivative for linesearch`），以前会退回“整条统一放慢”，比原配时还慢：普通航线 34.9 → 41.8 s，比赛航段 1 44.6 → 52.7 s，参考最高约 2.7～3 m/s。现在第一次没解出来时，会换 5 个起点再求解，取满足全部约束里最快的结果；全部失败才退回整体放慢。约束和上限都不变。`fly_points.sh` 的普通航线使用同一个求解器，同样适用。

- **只在第一次求解失败时触发**，正常能解出来的不变。
- 对流程的影响：轨迹准备时间增加约 1～7 s（在机载实测）。比赛航线一般在起飞前就准备好（起飞后起点对不上才重算），普通航线在起飞完成后准备；起飞后准备的这段时间飞机原地悬停等待。
- 日志里 `local_retiming.solver_retries` 记录重解次数，`solver_fallback: uniform_slowdown` 表示仍然退回了整体放慢。
- 回归测试：`src/airseafly_real400_mission/test/test_retiming_linesearch.py`，用两次实飞的空间曲线复现。
